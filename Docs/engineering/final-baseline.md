# Final Code-Architecture Baseline

DECIDED: ARCHITECTURAL_STYLE (Modular Monolith + Clean/Hexagonal + feature-oriented); ENGINEERING (OOP + SOLID + DI + explicit replaceable boundaries); DOMAIN (thin strict); CONTRACTS (consumer/application-owned); APPLICATION_ORCHESTRATION (narrow feature-scoped coordinators); PERSISTENCE (focused ports, no generic repository); DB_TRANSACTIONS (explicit narrow consistency); INTERNAL_EVENTS (explicit critical flow + lightweight typed notifications); ERROR_MODEL (typed expected outcomes + exceptions for unexpected); IMMUTABILITY (immutable facts + controlled mutable runtime); SHARED_STATE (explicit thread-safe owners); VALIDATION (boundary-specific); MAPPING (explicit boundary translation); CONFIG (layered ownership); OBSERVABILITY (separate channels); CANCELLATION (structured end-to-end); BACKGROUND_WORK (owned narrow hosted services); SERIALIZATION (explicit contract ownership + durable versioning); NULLABILITY (strict + explicit optional); IDS (lightweight strongly-typed); PUBLIC_API_VERSIONING (OpenAI /v1 + independent /api/v1); DEPENDENCIES (conservative/framework-first); TESTING (unit + contract + integration + limited E2E); FEATURE_FLAGS (experimental/risky only); HEALTH (separate liveness/readiness/provider-route); STARTUP (fail-fast for invalid mandatory bootstrap).
